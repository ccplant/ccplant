# クイックスタート

このガイドでは、実行先の確認、AIプロバイダーの認証、最初のセッションの作成までを案内します。

## 1. 実行先を用意する

ccplantでセッションを実行するには、利用できるPoolが必要です。契約内容に応じて、次のどちらかへ進んでください。

### Managed Poolを契約している方

Poolのセットアップは不要です。契約時に用意されたManaged Poolをそのまま利用できます。

ccplantへログインし、設定の「プール」に契約済みのManaged Poolが表示されることを確認します。

::: tip Poolが表示されない場合
画面を再読み込みしても契約済みのManaged Poolが表示されない場合は、契約先の管理者へお問い合わせください。ご自身でPoolをセットアップする必要はありません。
:::

### Managed Poolを契約していない方

セッションの実行基盤を用意し、Poolへ接続する必要があります。[Session Managerをセットアップする](./session-manager)へ進んでください。セットアップ後にccplantへ戻り、設定の「プール」で利用できるPoolを確認します。

## 2. AIプロバイダーを認証する

利用する接続方式を一つ選び、対応する設定を行います。個人のセッションで使う場合は個人設定を、チームで共有する場合は設定のスコープを対象チームへ切り替えてから操作してください。

### Codexのデバイス認証を使う

1. ccplantの設定を開き、「Codex 認証」へ進みます。
2. 「デバイス認証を開始」を選択します。
3. 表示されたURLをブラウザで開き、表示されたコードを入力してOpenAIアカウントで認証します。
4. ccplantへ戻り、「認証が完了しました」と表示されるまで待ちます。認証情報は選択中の個人またはチームスコープの`auth.json`として保存され、セッション開始時に自動で配置されます。

::: warning デバイスコードを共有しない
表示されたデバイスコードは、チャットやIssueなどへ貼り付けないでください。身に覚えのない認証要求はキャンセルしてください。
:::

デバイス認証を開始できない場合は、管理者へ利用可否を確認してください。手元に有効な`~/.codex/auth.json`がある場合は、「手動でアップロード」から登録することもできます。

### OpenAI API keyを使う

1. [OpenAI Platform](https://platform.openai.com/api-keys)でAPI keyを作成します。
2. ccplantの設定で「Codex 認証」を開きます。
3. 「Codex の接続方式」で「OpenAI 互換 API（Responses API）」を選択します。
4. 「デフォルトモデル ID」に利用するOpenAIモデルのIDを入力します。
5. 「Base URL」に`https://api.openai.com/v1`を入力します。
6. 「認証」で「API キー」を選び、「API キー / トークン」に作成したキーを入力します。
7. 「保存して使用」を選択します。保存した設定は次に作成するセッションから適用されます。

### OpenAI互換APIを使う

接続先がResponses APIと互換性のあるAPIを提供していることを確認してから設定します。

1. ccplantの設定で「Codex 認証」を開きます。
2. 「Codex の接続方式」で「OpenAI 互換 API（Responses API）」を選択します。
3. 接続先が提供するモデルIDとBase URLを入力します。Base URLには`/responses`などの個別エンドポイントを含めず、APIのベースとなるURLを指定します。
4. 接続先に応じて「API キー」または「認証なし」を選択します。APIキーを使う場合は「API キー / トークン」へ入力します。
5. 接続先がWeb searchに対応していない場合は、「Web search tool」を「無効」にします。
6. 「保存して使用」を選択します。

### Anthropic API keyを使う

1. ccplantの設定で「Claude Code 認証」を開きます。
2. 「接続方式」で「Anthropic 互換 API（Messages API）」を選択します。
3. 「デフォルトモデル ID」に利用するClaudeモデルのIDを入力します。
4. 「Base URL」にAnthropic APIのベースURLを入力します。`/v1/messages`は含めません。
5. 「API キー / トークン」にAnthropic API keyを入力します。
6. 「保存して使用」を選択します。

### Amazon Bedrockを使う

1. ccplantの設定で「Claude Code 認証」を開きます。
2. 「接続方式」で「Amazon Bedrock」を選択し、利用するモデルIDを入力して「保存して使用」を選択します。
3. 同じページの「Amazon Bedrock」で「Enable Bedrock」を有効にし、BedrockのモデルIDを確認します。
4. AWSの認証情報をccplantで管理する場合は、設定のスコープを対象チームへ切り替え、「Access Key ID」と「Secret Access Key」を入力します。
5. 画面下部に未保存の変更が表示された場合は「保存」を選択します。

Session Managerなど実行環境側でAWS認証を提供している場合は、ccplantへAccess Key IDとSecret Access Keyを保存せず、その認証を利用できます。どちらの方法を使うかは管理者へ確認してください。

::: warning API keyを安全に管理する
API keyやAWSの認証情報を初期メッセージ、チャット、リポジトリへ貼り付けないでください。漏えいが疑われる場合は、提供元でキーを無効化またはローテーションしてください。
:::

## 3. セッションを作成する

1. 画面上部の「新しいセッション」を選択します。
2. 「初期メッセージ」に、エージェントへ依頼する内容を入力します。この項目は必須です。
3. コードを使う場合は、「対象リポジトリ」に`owner/repository`形式で入力します。必要に応じてブランチまたはPull Request番号も指定します。リポジトリを指定しない場合は一般的なチャットとして開始されます。
4. 必要に応じてセッションプロファイルを選択します。初回は「自動選択」のままでも構いません。
5. 「その他の設定」を開き、Codex、OpenAI API、OpenAI互換APIを設定した場合は「Codex ACP」を、Anthropic APIまたはAmazon Bedrockを設定した場合は「Claude ACP」をエージェントタイプとして選択します。複数のPoolがある場合は、ここで実行Poolを指定できます。未指定の場合は利用可能なPoolから自動選択されます。
6. 「セッションを開始」を選択します。

セッションの作成が完了するとセッション一覧へ移動します。起動処理が終わったらセッションを開き、エージェントからの応答を確認してください。以降はメッセージを追加して作業を継続できます。

::: tip よく使う設定をまとめる
エージェント、モデル、Pool、環境変数などを毎回指定する場合は、セッションプロファイルとして保存しておくと再利用できます。
:::
